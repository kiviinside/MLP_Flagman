# MLP — система управления рестораном

MLP — веб-сайт для контроля основных процессов ресторана: складских остатков, поставок, заказов, блюд, сроков годности и списаний. Интерфейс предоставляет сводную информацию и аналитику, помогая сотрудникам быстрее находить нужные данные и отслеживать состояние запасов.

## Возможности

- **Главная панель:** сводные показатели и события.
- **Поставки:** просмотр и оформление поставок.
- **Заказы:** создание заказов и отслеживание их статусов.
- **Блюда и ингредиенты:** каталог блюд и связь с необходимыми продуктами.
- **Склад:** просмотр остатков и контроль минимальных запасов.
- **Сроки годности:** отслеживание партий и сроков хранения продуктов.
- **Стоп-лист:** контроль блюд, временно недоступных для заказа.
- **Горячие предложения:** отображение предложений на основе состояния запасов.
- **Аналитика:** графики динамики остатков и статистика списаний.
- **Списания:** учёт продуктов, выведенных из оборота.
- **Настройки интерфейса:** светлая, тёмная и системная темы.
- **Авторизация и роли пользователей:** предусмотрены серверной частью приложения.

## Запуск локально

### 1. Запустить backend

В терминале перейдите в папку backend:

```bash
cd backend
```

Запустите приложение через Maven:

```bash
mvn spring-boot:run
```

По умолчанию API запускается на `http://localhost:8080`.

### 2. Запустить frontend

Откройте второй терминал и перейдите в папку frontend:

```bash
cd frontend
npm install
npm run dev
```

Vite запускает интерфейс на `http://localhost:5173`. В конфигурации разработки запросы с путём `/api` проксируются на backend `http://localhost:8080`.

Откройте адрес frontend в браузере: <http://localhost:5173>.

## Настройка окружения

В папках `frontend/` и `backend/` находятся файлы `.env.example` с примерами переменных окружения. При необходимости скопируйте их в `.env` и измените значения для своей среды. Не публикуйте реальные пароли и секреты в репозитории.

Для frontend переменная `VITE_API_URL` задаёт базовый адрес API, если приложение должно обращаться к удалённому серверу. Для локальной разработки используйте прокси Vite и локальный backend.

Для запуска backend с PostgreSQL задайте переменные окружения:

```env
SPRING_PROFILES_ACTIVE=prod
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/flagman
SPRING_DATASOURCE_USERNAME=имя_пользователя
SPRING_DATASOURCE_PASSWORD=пароль
CORS_ALLOWED_ORIGINS=http://localhost:5173
```

Создайте базу данных `flagman` и убедитесь, что PostgreSQL доступен по указанному адресу. В production-профиле приложение использует PostgreSQL и Flyway для миграций. SQL-схема и дополнительные скрипты находятся в папке `database/`.

## API и документация

Backend предоставляет REST API для основных разделов приложения. При включённом Springdoc UI документация API обычно доступна по адресу:

- Swagger UI: <http://localhost:8080/swagger-ui/index.html>
- OpenAPI JSON: <http://localhost:8080/v3/api-docs>

## Разработка и проверка


Сборка backend:

```bash

```

## Примечания

- Адреса и параметры подключения зависят от локального окружения и настроек развёртывания.
- Для production-среды необходимо задать надёжные учётные данные, проверить CORS и настроить секреты вне репозитория.
- Демонстрационные данные могут использоваться для ознакомления с интерфейсом.
